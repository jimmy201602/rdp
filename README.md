# 独立 Go RDP 内核

本目录是独立 Go module，不导入父项目的 GPL 包。它是闭源迁移的分阶段实现，不是已经完成的完整 RDP 客户端、服务端或网关。

G3-1（服务端角色最小链路）：`server` 包实现 TLS-only 的 RDP 服务端：X.224 协商只接受含 PROTOCOL_SSL 的请求（否则回 RDP_NEG_FAILURE SSL_REQUIRED_BY_SERVER）、Go 标准库 TLS 服务端握手（证书由调用方提供）、MCS Connect-Initial/Response（SC_CORE 回显 PROTOCOL_SSL、SC_SECURITY ENCRYPTION_NONE、SC_NET 按客户端请求分配静态通道号）、Erect Domain / Attach User / Channel Join、解码 Client Info 后把用户名/域/密码交给调用方的 `Authorize` 策略回调（密码只在回调期间可见，不记日志、不落 Summary；拒绝时先完成许可，再发 Set Error Info ERRINFO_SERVER_DENIED_CONNECTION 和 Disconnect Provider Ultimatum）、许可以 STATUS_VALID_CLIENT 结束、Demand Active（General/Bitmap 24bpp/Order/Pointer/Input/Share/Font/ColorCache/VirtualChannel）→ 校验 Confirm Active（取客户端首选色深 16/24/32）、收客户端 Synchronize/Control/Font List 后回 Synchronize/Control Cooperate/Granted/Font Map，然后按客户端色深推送未压缩 Bitmap Update（分块 ≤16 KB）和一枚 24bpp 彩色指针；激活后读循环丢弃慢路径/fast-path 输入（G3-2 再路由），Refresh Rect 重发帧，Shutdown Request 或客户端 DPU 时关闭。握手超时、空闲超时、并发上限、每连接 goroutine 随 `Serve` 上下文取消而退出。`cmd/rdpserve` 是对应的验证 CLI。服务端不连接任何上游目标（G3-3 网关再做），也不做 NLA/CredSSP、Standard RDP Security、输入处理、虚拟通道数据或 orders。

当前里程碑：TPKT 帧、X.224 安全协议协商、严格验证服务器证书的 TLS，MCS Connect-Initial/Response（BER）与 GCC Basic Settings Exchange（PER，含对协商结果的重确认），Erect Domain / Attach User / Channel Join（用户通道 + I/O 通道），Client Info PDU（Secure Settings Exchange），MS-RDPELE 许可（New License Request / Platform Challenge Response / STATUS_VALID_CLIENT / New·Upgrade License MAC 校验），Demand Active / Confirm Active 能力交换，Synchronize / Control / Font List / Font Map 连接收尾，以及 Font Map 之后的服务端输出观察（Save Session Info 登录通知、Slow-Path Update / Pointer 分类计数、Deactivate All 重激活），Fast-Path 输出（TS_FP_UPDATE_PDU 按首字节与 TPKT 区分、分片重组、各 updateCode 分发到同一套处理），Bitmap Update 解码（Interleaved RLE 解压，8/15/16/24/32bpp 与 Palette Update 转 RGBA 帧缓冲，`rdpprobe -png` 可导出），以及指针渲染（Color/New/Large 指针的 XOR/AND 掩码转 RGBA 光标、按 Pointer Capability 容量缓存、Cached/Position/Null/Default 状态，`rdpprobe -cursor-png` 导出，位置已知时合成到 `-png`；orders 不解析）；单元/fuzz 测试和隔离 xrdp 互操作验证到 Font Map 后解码出的 xrdp 登录界面 / xfce 桌面画面与光标。只请求 TLS；不支持 TLS-only 的目标应明确失败，不回退到 Standard RDP Security 或绕过 NLA。`Probe`/`Connect` 不发送 Client Info；`Activate` 发送 Client Info，只有调用方显式给出密码时才设置 INFO_AUTOLOGON。

内核要求 `CGO_ENABLED=0` 可构建，使用 Go 标准库，不引入协议替身。UI、OCR 和视频导出属于后续独立审核范围。

仅在明确授权的目标上运行。不得把 TLS、Channel Join 或 Font Map 解释为用户已认证、桌面已显示或完整 RDP 会话已通过：Font Map 之后只解码 Bitmap Update 与指针（orders、Surface Commands、编解码器不处理），没有输入和虚拟通道；发送凭据时本工具只报告收到的 Save Session Info / Set Error Info，服务端不发（xrdp 0.9.24 就不发）时登录结果仍不可知。尚未实现：NLA/CredSSP、Standard RDP Security、基础位图/指针之外的图形、输入、虚拟通道。服务端角色（`server`/`rdpserve`）同样只到 G3-1：静态测试图案和一枚光标，不是桌面，不代理任何目标，输入被丢弃；真实客户端验证只做了 xfreerdp 2.6.1（见 `docs/VALIDATION.md` 5.7），mstsc 未测。
